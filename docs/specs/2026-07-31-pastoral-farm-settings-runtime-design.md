# Pastoral 农牧、设置与酒馆运行机制设计

日期：2026-07-31

## 概述

本轮在现有原生 JavaScript、MVU 数据驱动、模块化打包架构上修复酒馆运行问题，并扩展可伸缩农牧系统、提示词设置和可核对的归寝日结流程。模块源码继续位于 `css/` 与 `js/`，由 `build.js` 打入自包含 `index.html`。

## 目标

- 第 0 层成为唯一页面宿主，隐藏酒馆父页面第 1 层及后续楼层，但保留酒馆原生输入区。
- 修复设置按钮不可交互问题，提供接口设置与更新提示词两个页面。
- 普通更新、归寝日结提示词可存入 `mrfz_settings`；空值使用程序内置默认提示词。
- 快捷动作追加到卡内输入框，不覆盖玩家已有内容。
- 归寝必须二次确认，并提供发送、等待、结算、写回和结果反馈。
- 支持新版动态普通农田、魔法农田、种子图鉴、堆肥箱和畜牧结构。
- 设施引力完全由前端脚本根据已建成建筑计算和更新，并提交给 AI。
- 日结扣除员工薪资、建筑维护费，并更新植物成长剩余日期及每日农牧状态。
- 当日预报显示并维护 `日初资金`，用于日结对账。
- 副 API 更新在目标消息无 `UpdateVariable` 标签时追加标签；副 API 返回裸 MVU 命令时安全包装。

## 非目标

- 不引入 Vue、React 或 CSS 框架。
- 不为每个农事动作分别设置提示词。
- 不把 API Key 写入源码。
- 普通交互不在前端擅自修改游戏状态；脚本确定性计算仅限设施引力与归寝日结的明确数值规则。

## 1. 酒馆宿主接管

`js/host.js` 在第 0 层 iframe 初始化后向同源父文档注入接管样式：

- 隐藏 `#chat` 中所有非第 0 层 `.mes`。
- 保留第 0 层及酒馆原生输入区。
- 卡内仍通过酒馆 API 读取并渲染全部聊天记录。
- 监听父文档聊天 DOM 变化，重新应用接管标记。
- 非第 0 层 iframe 自我销毁。
- 页面卸载时移除本页面接管标记；全屏逻辑继续只放大当前 iframe。

## 2. 输入叠加

`Chat.compose(text, kind)` 使用换行追加：

- 输入为空时直接写入。
- 已有内容时保留原内容并追加新动作。
- 连续快捷动作依次累积。
- 发送成功后清空；发送失败恢复发送前文本。
- 归寝动作仅在玩家确认后追加并发送。

## 3. 设置页面

设置由右上浮卡改为有遮罩、焦点圈定和键盘支持的页面式对话框。

### 接口设置

- 单 API / 多 API。
- 副 API URL、Key、模型、超时、重试。
- 手动重试最近失败的副 API 请求。

### 更新提示词

- `prompts.normal`：普通变量更新。
- `prompts.endday`：归寝日结。
- 初始值均为空字符串。
- 空值不复制默认文本到缓存，运行时使用内置默认值。
- 非空值替换对应“任务要求”，而历史、规则、快照、脚本计算数据和输出约束由程序拼接。
- 提供恢复默认按钮（清空字段）。

所有数据存入 `mrfz_settings`，深度合并并保留未知旧字段。

## 4. 设施引力确定性计算

设施六维引力不再信任 AI 写入的 `访客生态.设施引力`，完全由脚本计算：

1. 遍历 `建筑.已建成`。
2. 对每个建筑的 `影响力.{美食,知识,舒适,冒险,文化,自然}` 分别求和。
3. 每个维度的最终设施引力就是该维度的子引力总和，不做除法或平均。
4. 子引力总和原样填入 `访客生态.设施引力` 的对应维度；对结果采用稳定的小数格式，避免无意义浮点尾数。
5. 脚本把结果同步更新到当前 MVU 快照的 `访客生态.设施引力`。
6. `总引力值`按 `声望引力 + 六维设施引力合计 + 服务引力 + 环境引力` 同步计算。
7. 普通请求和归寝请求都把脚本计算结果作为只读事实提交给 AI，明确禁止 AI 重算或覆盖算法。
8. UI 雷达、公式和详情统一使用脚本结果；建筑原始影响力等其余项目仅供玩家阅读。

若 MVU 未就绪，独立预览只在内存样例上计算，不写宿主数据。

## 5. 农牧页面

农牧面板包含四个子页：普通农田、魔法农田、种子图鉴、畜牧与堆肥。

### 普通农田

- 读取 `农田大小` 动态生成网格。
- 大尺寸网格横向滚动，格子保持可触控尺寸。
- 设置安全渲染上限，异常尺寸显示提示。
- 范围外旧记录保留展示。
- 详情显示状态、作物、剩余天数、浇水、施肥、品质、过熟天数、已收获次数和连续收获信息。
- 开垦、播种、浇水、收获操作追加到输入框。

### 魔法农田

- 未解锁时显示锁定空状态。
- 解锁后按独立大小和网格渲染。
- 额外展示魔力灌溉、养护、稳定度、连续未养护天数、变异状态和环境标签。
- 魔力灌溉与养护操作追加到输入框。

### 种子图鉴

- 动态读取全部种子。
- 支持名称搜索和普通/魔法筛选。
- 展示季节、生长、产出、价格、来源、特殊条件、连续收获、间隔、上限、永续、效果和描述。
- “用于播种”只追加意图，不直接改变量。

### 畜牧与堆肥

- 堆肥显示状态和倒计时。
- 畜牧动态显示设施名、饲料倒计时、产出倒计时和健康度。
- 操作只追加自然语言意图。

## 6. 归寝确认与确定性日结

点击归寝按钮先打开确认框，取消或 Escape 不发送、不改输入。确认按钮显示完整待发送文本，并在处理期间禁用重复操作。

### 阶段反馈

- 正在发送归寝行动。
- 正在等待剧情。
- 正在核算今日账簿。
- 正在写回变量。
- 日结完成或失败。

### 脚本确定性结算

归寝生成结束后，以主剧情更新后的最新 MVU 快照为基准，脚本执行明确规则：

- 员工薪资：汇总 `旅店.员工.*.职业信息.日薪` 并从资金扣除。
- 建筑维护：汇总 `建筑.已建成.*.维护费用` 并从资金扣除。
- 普通农田：种植中作物的 `剩余天数` 每日减少 1（最低为 0），随后重置 `今日已浇水`；其他字段不凭空推断。
- 魔法农田：种植中作物的 `剩余天数` 每日减少 1（最低为 0），随后重置 `今日已浇水`、`今日已魔力灌溉`、`今日已养护`；稳定度、变异和未养护惩罚若没有明确算法则交由规则/AI更新，不由前端臆造。
- 堆肥和畜牧倒计时的自动变化仅在变量规则或自定义提示词要求时由 AI 处理；前端不假定产出算法。
- 设施引力按固定脚本算法重算。

确定性结算结果作为“已完成事实”提交给日结 AI；AI负责天气、潜在访客、注意事项及规则定义的其他变化，不得重复扣费或重复减少植物天数。

### 防重复

日结请求带唯一周期标识，仅允许对同一归寝消息执行一次确定性结算；重试副 API 或重绘 UI 不得重复扣费、重复推进作物。

## 7. 日初资金与结果账簿

日结前读取：

- 当天 `当日预报.日初资金`。
- 归寝前资金。

日结后写入：

- 新一天 `当日预报.日初资金 = 日结完成后的最终资金`。

结果账簿显示：

- 结算来源。
- 日期变化。
- 原日初资金。
- 归寝前资金。
- 员工薪资总额。
- 建筑维护费总额。
- 日结后资金。
- 当日经营变化、日结变化、全天净变化。
- 新天气、新引力和模型总结。

缺失数值显示“暂无数据”，不误显示为 0。

## 8. UpdateVariable 写回

- 目标消息已有标签：移除旧标签，末尾追加副 API 新标签，最终只保留一个。
- 目标消息无标签：末尾追加新标签。
- 副 API 返回无标签但包含可识别 MVU 命令：提取命令并包装为完整标签。
- 完全无有效更新命令：按重试策略重试，最终保留主 API 结果并显示错误。
- 剧情、总结和选项保持原顺序。

## 9. 错误恢复

- 主剧情发送失败：不日结，恢复输入内容。
- 确定性结算失败：不报告成功，显示失败阶段。
- 副 API 失败：降级主 API；可在设置页手动重试，但确定性扣费和作物推进不重复执行。
- 设置保存失败：保留表单内容并显示错误。
