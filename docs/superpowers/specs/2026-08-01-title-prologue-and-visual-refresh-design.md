# 标题界面、强制序章与正式前端全面焕新设计

**日期：** 2026-08-01  
**状态：** 已批准  
**项目：** Pastoral / 暮归旅店伪同层双页前端

## 1. 目标与范围

本次更新增加一个加载后优先出现的标题界面，在新聊天只有第 0 层时强制展示完整开局文本，同时对正式双页前端进行不改变功能的全面视觉焕新，并把库存物品图标自定义扩展成跨模块的同名资源图标联动。

必须保留现有：

- 第 0 层唯一宿主与伪同层聊天接管；
- 主剧情发送、第二 API、固定预设短事务和 MVU 读写/结算；
- 标签顺序、八个经营面板及其数据含义；
- 手机沉浸模式的经营页/剧情页切换；
- 员工详情展开；
- 聊天编辑、复制、删除、选项和输入流程；
- 昼夜主题、设置和全屏功能。

本次不重构上述业务逻辑，只增加启动门控、序章显示、资源图标适配和样式层。

## 2. 视觉方向

采用用户选择的 **A「山谷暮光」**。设计语言为“翠玉摇篮的电影式暮光景观 × 羊皮纸魔法经营志”，继续使用项目已有的暖羊皮纸、墨绿、琥珀金、薄荷魔法蓝、暖棕墨与深靛夜色。

标题页背景由 CSS 渐变、内联 SVG 和矢量剪影组成，避免外部图片依赖，保证构建产物继续是自包含 HTML。画面包含：

- 蜜金到深蓝的暮色天空与远山；
- 湖面薄雾与低亮度反光；
- 山谷中央亮灯的两层旅店；
- 前景老槐树和草坡剪影；
- 少量萤火、纸张颗粒和边缘暗角。

正式界面不另起风格，而是将同一色彩、光线与纹理延续到双页书中。

## 3. 标题界面

### 3.1 内容

标题界面包含：

- 游戏名：`我们的家族又没落了？`
- 作者：`观心`
- 发布说明：`卡免费发布 · 类脑 / 旅程`
- 作者卡楼链接：`https://discord.com/channels/1380075940285124724/1480878747291881654`
- 主操作按钮：`开始游戏`

作者卡楼使用普通可聚焦链接并在新标签页打开，设置 `rel="noopener noreferrer"`。标题层在开始游戏前阻止底层正式界面被鼠标、触摸或键盘误操作。

### 3.2 入场与互动

在允许动效时，标题页按层次在约 1.2–1.8 秒内完成入场：山谷、湖雾、旅店灯光、前景老槐树、墨迹标题、作者信息和按钮依次出现。开始按钮悬停时显示琥珀边缘流光和萤火聚拢，按下时有轻微纸面回弹与光晕扩散。

`prefers-reduced-motion: reduce` 下取消粒子、视差和连续漂移，只保留极短淡入淡出。所有按钮和链接具备清晰焦点环，触控面积至少 44×44px。

### 3.3 启动状态

标题层只在本次页面生命周期内显示一次，不写入 localStorage，避免刷新或切换聊天后永久跳过标题。点击开始后按钮进入 `aria-busy` 状态并临时禁用，防止重复触发。

## 4. 楼层检测与显示决策

点击开始游戏时通过酒馆助手 `getLastMessageId()` 检测最新楼层：

1. **最新楼层为 0：** 不读取或渲染第 0 层正文，直接使用内置完整开局文本进入序章。
2. **最新楼层大于 0：** 不重复显示序章，标题层退场后直接显示现有正式界面与聊天记录。
3. **酒馆 API 不存在：** 视为独立预览，显示内置序章及样例状态。
4. **楼层 API 抛错或返回非法值：** 显示非阻塞提示，按独立预览降级，确保开始按钮不会卡死。

第 0 层可能经酒馆正则后只剩 Markdown 围栏 ``````。本设计明确禁止将第 0 层正文作为序章来源，因此该内容不能覆盖或阻断内置开局文本。

强制序章仅用于显示：不写回第 0 层、不增加聊天楼层、不触发模型、不修改 MVU。出现真实新楼层后，现有 `Chat` 轮询与渲染链路继续正常工作。

## 5. 强制开局文本与序章卷轴

### 5.1 文本来源

用户提供的完整开局文本以只读常量形式保存在源码中。为避免大段 HTML 字符串不可维护，正文数据与展示结构分离：保存完整原文，并由确定性的序章渲染器按已知边界生成语义段落。不得摘要、删改或改写原文。

### 5.2 章节结构

序章按照以下结构显示：

1. **时间铭牌**：`【第一年，春季第1天，周一，晴天。7:00】`
2. **信鸽来信**：从“信是三天前到的”到“信的内容如下”
3. **叔公来信**：从“吾之后辈，见字如晤”到附言结束
4. **抵达山谷**：从“从白帆城出发”到旅店内部初见
5. **艾莉初见**：艾莉的自我介绍、旅店现状与欢迎语
6. **清晨新生**：从“那是昨晚的事了”到清晨景观及经营抉择
7. **委托任务**：`初来乍到`、完整描述和 `声望+3`

### 5.3 美化规则

- 时间铭牌使用日晷、晴天和时间图标，采用琥珀金与墨绿。
- 信鸽章节带低对比度信鸽、蜡封和窗台线稿。
- 叔公来信置于不规则羊皮信纸，含折痕、纤维、老槐树与灯的纹章水印、装饰首字、右对齐署名、附言分隔和不遮挡正文的蜡封。
- 旅程章节用小型路线节点表示白帆城、格林镇和翠玉摇篮。
- 艾莉对白使用浅蓝细线强调，不制造头像或聊天气泡。
- 清晨章节提高纸面亮度并加入低对比度晨光。
- 委托任务显示为卷轴任务卡，但不增加按钮或本地任务操作。

长文不使用逐字打字机。章节可分批淡入，但用户进入后立即可以滚动，动画不得锁定阅读。序章容器使用正常滚动和受限文本行宽，桌面正文不超过约 72ch。

## 6. 正式双页前端全面焕新

### 6.1 不变的结构与功能

保持 `src/template.html` 的双页语义结构和所有现有 ID、数据属性及事件目标，必要时只增加装饰容器或类名。业务函数签名、轮询频率、事件名称和数据读取方式不因视觉更新改变。

### 6.2 页面框架

- 书页增加纸张厚度、柔和翘边、页角暗纹和左右页轻微不同的光线。
- 书脊增加缝线、压痕和低亮度装订点。
- 最大宽度保持 1200px。
- 桌面双页等宽；手机沿用现有单页沉浸切换、安全区和 `100dvh` 处理。

### 6.3 导航与 HUD

- 八个标签顺序与点击行为不变。
- 标签图标统一尺寸和视觉重量；激活态使用墨迹下划线、纸签抬升和琥珀微光。
- 日期与天气组成“今日铭牌”；旅店名继续是 HUD 中央焦点。
- 资金、声望和状态条强化数值层级，状态条增加低调纸纹和光点。
- 所有数值来源、格式化和刷新逻辑保持不变。

### 6.4 卡片与面板

建筑、库存、员工、访客、任务、农牧等统一使用分层纸面基础组件：

- 以左侧色标、图标和局部语义色区分类型；
- 降低相同阴影的重复使用，以纸张层次和留白建立层级；
- hover、focus、active 状态统一为 150–300ms 过渡；
- 信息本身和现有操作不删减；
- 空状态保留说明并升级为线稿图标、标题和指引；
- 异步区域使用纸面扫光或墨迹晕染骨架，不能突然空白。

### 6.5 正文与输入

- AI 内容呈现为经营日志叙事段落，用户行动保留克制的纸条卡片，系统内容作为细线注记。
- 引用、强调、列表与模型保留的内联美化统一排版，最大阅读宽度约 66–72ch。
- 选项改为带序号纹章的行动纸条，但仍只调用现有填入输入框逻辑。
- 输入框呈现为待写入日志的空白行；聚焦时显示薄荷蓝到琥珀金的轻微边缘变化。
- 发送、生成中、成功和错误状态继续使用现有逻辑，只替换视觉表现。
- 右键编辑、复制、删除及两步删除确认完全保留。

### 6.6 设置、弹窗与吐司

保留现有 DOM 和事件行为，统一改为浮动纸页。焦点陷阱、Escape 关闭、ARIA 及键盘顺序不变。昼夜主题都满足 WCAG AA 文本对比。

## 7. 同名资源图标系统

### 7.1 需求

库存物品图标应像地图地块和农田图标一样可点击并打开现有 `IconPicker`。选择的图标必须联动所有明确的同名资源展示：

- 库存物品；
- 种子图鉴；
- 普通与魔法农田作物；
- 食谱材料；
- 其他以相同资源名明确渲染的资源位置。

该能力只改变显示，不修改 MVU。

### 7.2 统一资源键

资源共享键使用：

```text
resource:<规范化名称>
```

名称规范化规则：

1. 转为字符串并去除首尾空白；
2. 连续空白合并为一个空格；
3. 对种子额外推导基础作物名，如 `春小麦种子` → `春小麦`；
4. 不做包含关系或模糊匹配，避免把 `晨露麦粉` 错误合并到 `晨露麦`；
5. 精确资源键优先于推导的基础作物键。

默认图标仍通过现有名称推断函数选择。自定义图标继续由现有 Assets/IconPicker 本地持久化，不上传、不写入聊天或 MVU。

### 7.3 交互范围

资源图标调用现有 `replaceableIcon`/`IconPicker.decorate` 能力，点击目标使用语义按钮、可访问标签和键盘操作。选择器支持搜索、选择和恢复默认。

用户选择的是同名全局资源样式，因此本次资源入口不提供“仅当前库存格”的分叉，避免同一资源出现不一致显示；地图坐标、农田格等现有目标级覆盖能力保持原样。

### 7.4 食谱材料

食谱材料目前是自由文本字符串。新增纯展示解析器：

- 从当前状态收集库存名、种子基础名和农田作物名作为已知资源；
- 按最长精确名称优先识别材料文本，保留原顺序、标点和未识别片段；
- 为识别出的资源片段增加小图标与原文字；
- 未识别或解析失败时完整回退原材料字符串；
- 不据此判断材料数量、不禁用食谱、不改变烹饪意图文本。

## 8. 模块边界与数据流

### 8.1 `TitleScreen`

负责标题场景、作者信息、外链、开始按钮、楼层检测和标题离场。它只返回启动决策：`prologue` 或 `resume`，不读取 MVU、不渲染聊天。

### 8.2 `Prologue`

负责内置原文、章节划分和序章 DOM。它不访问聊天写接口、不触发模型、不写 MVU。

### 8.3 `ResourceIcon`

负责资源名规范化、共享键、默认图标推断、已知资源收集和食谱材料装饰。它调用现有图标选择器，不管理库存数量或农牧规则。

### 8.4 初始化顺序

1. `Host.init()` 判断是否为唯一宿主；非宿主仍立即自毁。
2. 标题层渲染并允许已有底层模块在不可交互状态下完成必要初始化。
3. 点击开始后 `TitleScreen` 检测最新楼层。
4. `resume`：标题退场，解除正式界面不可交互状态。
5. `prologue`：标题退场并展示 `Prologue`；正式界面在序章之后自然衔接。
6. 后续聊天与状态更新仍由现有 `Chat`、`MVU`、`Render` 和 `App` 处理。

若为避免初始加载开销而延后部分初始化，必须保证开始后初始化顺序仍是 Icon/Assets → MVU → Chat → Render，且不能改变现有事件绑定次数。

## 9. 响应式与可访问性

- 移动优先，从 375px 验证。
- 使用现有项目断点习惯，并在 640、768、1024、1280px 附近检查布局。
- 标题使用 `clamp()`，长链接以可换行文本显示。
- 所有交互目标至少 44×44px；鼠标交互均有键盘等价操作。
- 标题层、序章和正式界面具有正确的 `main`、`section`、`article`、`header`、`nav`、`button` 和 `a` 语义。
- 标题离场后焦点移到序章标题或正式界面的首个主要区域；序章不设置焦点陷阱。
- 图标按钮带 `aria-label`；动态状态使用现有 `aria-live`，避免额外噪声。
- 所有连续动画受 `prefers-reduced-motion` 保护。

## 10. 异常与降级

- 酒馆楼层 API 不存在或失败：按独立预览显示序章，并通过内联提示说明已使用预览模式。
- 第 0 层内容为空、只有代码围栏或被正则清除：仍显示内置完整序章。
- 图标数据库不可用：保持推断的内置 SVG 图标并显示非阻塞提示。
- 食谱材料无法解析：原字符串逐字保留。
- 夜间主题：标题保持暮色；信件内部保持暖纸以维持可读性，外围使用深靛环境。
- 任何视觉增强失败都不得阻塞聊天、MVU 或正式功能。

## 11. 测试与验收

采用 TDD，并至少覆盖：

1. 页面加载时标题层存在且底层不可误操作。
2. 游戏名、作者、发布说明和 Discord 链接正确。
3. 开始按钮调用最新楼层检测且防止重复点击。
4. 最新楼层为 0 时渲染内置完整开局文本。
5. 第 0 层只有代码围栏时仍显示完整序章。
6. 最新楼层大于 0 时不显示序章并恢复现有记录。
7. 独立预览和 API 异常降级可用。
8. 时间铭牌、来信、旅程、艾莉对白、清晨和任务卡具有预期语义结构。
9. 序章不调用聊天写入、生成或 MVU 写回。
10. 库存图标能打开选择器。
11. 同名库存、种子、作物和食谱材料使用相同资源键。
12. 恢复默认后所有同名展示同步恢复。
13. 未识别食谱材料完整保留。
14. 现有标签、发送、编辑、删除、全屏、主题、设置、移动页切换和员工展开测试继续通过。
15. `npm test`、修改脚本 `node --check`、构建产物一致性及 `git diff --check` 通过。
16. 浏览器在 375px、768px 和桌面宽度检查标题、序章和正式双页界面。
17. 检查键盘导航、焦点环、颜色对比和减少动效模式。

## 12. 预计文件边界

实施计划可按实际测试结果调整，但预期涉及：

- `src/template.html`：标题层、序章挂载点和必要语义容器；
- `css/tokens.css`、`css/base.css`、`css/layout.css`、`css/components.css`、`css/animations.css`：全面视觉系统升级；
- 新的标题/序章/资源图标模块，或在保持职责清晰的前提下加入现有模块；
- `js/render.js`、`js/app.js`、`js/icon-picker.js`/`js/assets.js` 的最小适配；
- `build.js`：若新增模块则更新内联顺序；
- `test/`：标题、序章、资源联动与回归测试；
- `index.html`、`public/index.html`：仅由构建生成。

不得把 `.superpowers/brainstorm/` 视觉伴侣临时产物纳入产品提交。

## 13. 完成标准

当且仅当以下条件同时满足时，任务才算完成：

- 标题页、楼层分支和强制序章按本规范工作；
- 用户提供的完整开局文本无删改显示；
- 正式前端完成全面视觉焕新且功能回归通过；
- 所有同名资源图标联动生效；
- 自包含构建生成成功；
- 自动测试与真实浏览器验收通过；
- 未纳入用户原有无关工作区改动或视觉伴侣临时文件。
