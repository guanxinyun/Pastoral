# 手机滚动、强制第二 API 与只读零层设计

**日期：** 2026-08-02
**状态：** 已批准
**目标：** 修复手机内嵌及全屏触控滚动与发送可达性，收紧变量请求为强制第二 API，精简预设模式，并确保第 0 层消息永不被开局流程覆盖。

## 一、范围与原则

本轮只处理以下行为：

1. 手机普通内嵌与真正全屏都能纵向滑动，所有底部操作可达。
2. 核验并保护卡内发送框的 `/send` → `/trigger await=true` 主剧情流程。
3. 变量处理强制使用第二 API，删除单 API 变量模式及主 API 变量回退。
4. 变量预设只保留“沿用酒馆当前预设”和“指定自定义预设”。
5. 第 0 层原消息完全只读，开局只在卡内渲染内置美化文本。
6. 删除发送输入框内部的横格纸背景。

主剧情仍使用酒馆当前主 API；“强制第二 API”仅指主回复后的普通变量更新和归寝变量更新。第二 API 失败不能删除或回滚已经生成的主剧情。

## 二、移动端滚动架构

### 2.1 手机普通内嵌

普通内嵌不显示“经营页 / 剧情页 / 退出”。iframe 保持在酒馆可视高度范围内，书本成为唯一纵向滚动容器：

1. 经营页完整出现在文档流中。
2. 玩家可继续下滑至经营页底部的主题、全屏、设置按钮。
3. 再继续下滑至剧情页、消息、选项、发送框和归寝按钮。

在该模式下，`.panels` 与 `.journal__stream` 不再作为独立的触摸滚动容器；它们按内容自然增高，避免手指落在面板或消息上时由嵌套滚动截获手势。书本使用 `overflow-y:auto`、`overscroll-behavior:contain`、`touch-action:pan-y` 及 WebKit 惯性滚动。

### 2.2 手机真正全屏

真正全屏显示“经营页 / 剧情页 / 退出”，一次只显示一页。顶部页签保持在书本顶部，当前可见页面是纵向滚动容器：

- 经营页可滑到主题、全屏和设置按钮。
- 剧情页可滑过 HUD、消息与选项，直至发送框和归寝按钮。
- `.panels` 与 `.journal__stream` 取消嵌套触摸滚动，由当前页面统一承载滚动。
- 经营页和剧情页分别保存滚动位置；切页后恢复对应位置。
- 退出全屏后清理单页状态，恢复普通内嵌整本书滚动。

桌面有界双页和桌面沉浸布局不改变。

## 三、发送与第二 API 前置校验

卡内发送的唯一入口仍为 `Chat.handleUnifiedRequest()`，点击发送和 Enter 共用该入口：

```text
读取并规范化输入
→ 校验第二 API URL / Key / Model
→ 校验通过后锁定输入控件
→ /send 玩家行动
→ /trigger await=true
→ 等待本次新的非 user AI 楼层
→ 第二 API 执行变量阶段
```

若第二 API 配置不完整：

- 不调用 `/send`，也不调用 `/trigger`；
- 输入框文本原样保留；
- 显示明确错误；
- 自动打开设置的接口页，并将焦点移至第一个缺失字段。

若主剧情已成功、第二 API 随后失败：

- 保留主剧情楼层；
- 不伪装变量更新成功；
- 登记 `lastFailure`；
- 保留现有“重新调用上次失败的第二 API”操作。

发送成功后仅在输入框仍等于本次正文时清空，避免覆盖玩家在异步期间输入的新内容。

## 四、强制第二 API 契约

### 4.1 设置模型

删除 `apiMode` UI 与运行时分支。设置仅保留第二 API 的 URL、Key、模型、超时和重试次数。

加载旧缓存时：

- 忽略并删除 `apiMode`；
- 无论旧值为 `single` 或 `multi`，新运行时都采用强制第二 API；
- 保留未知的其他项目字段。

### 4.2 普通与归寝流程

普通请求：主剧情成功后必须调用第二 API 变量阶段。

归寝请求严格执行：

```text
主剧情回复
→ 第二 API 日常变量阶段
→ 脚本确定性结算
→ 第二 API 归寝变量阶段
→ 重新锁定确定性事实
→ 最终 MVU 写回
```

删除 `callMainApiForDaily()`、`appendDailyUpdate()` 以及所有单 API 日结分支。第二 API 失败时保留主剧情和已经完成的脚本确定性结算，并报告部分完成，不静默改用主 API。

## 五、变量预设精简

每个变量阶段仅保留两种模式：

1. `current`：沿用酒馆当前预设。
2. `fixed`：短暂切换到玩家指定预设，等待约 1 秒后发起，再保持约 2 秒提示词捕获窗口并恢复原预设。

删除：

- `none` 模式；
- `generateRaw` 无预设生产路径；
- 不带预设专属的八项上下文复选框；
- 相关说明与缓存字段。

旧缓存迁移：

- `mode:none` 或非法模式迁移为 `current`；
- `fixed` 与合法预设名保持不变；
- 删除旧 `context` 与 `assembly`；
- 普通和归寝的深度注入屏蔽、温度、固定预设名继续独立保存。

## 六、第 0 层只读开局

第 0 层只用于承载 iframe，不再承担开局正文存储。检测到最新楼层为 0 时：

- 直接用 `Intro.OPENING_TEXT` 构造卡内语义化、美化序章；
- 不读取第 0 层正文决定序章内容；
- 不调用 `setChatMessages()`、`deleteChatMessages()`、`triggerSlash()` 或 MVU 写回；
- 点击“进入旅店”只切换卡内 DOM 状态；
- 第 0 层原消息在流程前后逐字不变。

删除 `persistFloorZeroOpening()` 及相关等待、失败和重试状态。标题开始按钮不再因第 0 层写回失败而受阻。

聚合对话流仍可显示第 0 层自身内容；本轮只保证开局渲染不会覆盖它。

## 七、视觉调整

发送输入框删除重复横格线背景，改为项目令牌驱动的纯净表面背景。保留边框、阴影、焦点动画、禁用和加载状态，不改 AI 消息气泡左侧竖线。

## 八、测试与验收

### 8.1 滚动

- 手机普通内嵌：书本 `scrollHeight > clientHeight`，滚动可到全屏按钮、发送框及归寝按钮。
- 手机全屏经营页：页面可滚到底部设置按钮。
- 手机全屏剧情页：页面可滚到发送框和归寝按钮。
- 面板与消息流在手机模式不再形成嵌套滚动；桌面仍保持有界内部滚动。
- 切换经营/剧情页保存各自滚动位置。

### 8.2 发送

- 点击与 Enter 均各自产生一次 `/send` 和一次 `/trigger await=true`。
- Shift+Enter 只换行。
- 第二 API 配置缺失时 slash 调用次数为 0、输入不清空、设置打开并聚焦缺失字段。
- 主回复成功但第二 API 失败时，主楼层保留且可手动重试变量阶段。

### 8.3 设置与 API

- 设置页不存在 API 模式控件。
- 设置规范化结果不含 `apiMode`。
- 普通与归寝变量阶段都调用第二 API。
- 不存在主 API 静默日结回退。
- 预设下拉只包含 current/fixed；旧 none 迁移 current；不再显示八项上下文开关。

### 8.4 零层

- 新开局 `setChatMessages`、删除、slash、MVU 写回均为 0 次。
- 第 0 层任意原文在开始前后完全一致。
- 卡内仍完整显示内置开局、进入按钮和正式游戏切换。

### 8.5 视觉与回归

- 输入框 CSS 不含重复横线背景。
- `npm test`、修改脚本语法检查、bundle 一致性与 `git diff --check` 通过。
- 使用真实 SillyTavern iframe 在手机内嵌和原生全屏下完成滚动、发送前置校验与控件点击实测。
