# SillyTavern / TavernHelper / MVU 接口与时序速查

> 本文件是 `README.md` 的便携速查版。它只记录当前 Pastoral 已使用或迁移时需要的宿主契约，不替代目标环境中的实际类型定义与真机测试。

## 1. 消息与楼层

| 全局接口 | 作用 | 迁移注意 |
|---|---|---|
| `getCurrentMessageId()` | 当前 iframe 所在楼层 | 伪零层中恒为 0，只用于宿主判定 |
| `getLastMessageId()` | 当前聊天最后一楼 | 用于最新状态读取；异步写回仍应使用流程捕获的明确 ID |
| `getChatMessages(idOrRange)` | 读取单楼或范围消息 | 原始 `message` 未经过显示正则 |
| `setChatMessages(updates, options)` | 修改指定消息 | 用 `{refresh:'none'}` 避免宿主立即重复渲染 |
| `deleteChatMessages(ids)` | 删除指定消息 | 不可逆；0 楼宿主必须保护 |

常用调用：

```javascript
const latestId = getLastMessageId();
const latest = getChatMessages(latestId)?.[0];
const all = getChatMessages(`0-${latestId}`);
```

## 2. 正文处理

```javascript
formatAsTavernRegexedString(
  rawText,
  'ai_output',
  'display',
  { depth: 0 },
);
```

- 输入：消息原文。
- 输出：执行酒馆显示正则后的字符串，可能含 HTML。
- 不负责安全净化。
- 选项和 `UpdateVariable` 必须优先从原文提取。

## 3. MVU

初始化：

```javascript
await waitGlobalInitialized('Mvu');
```

读取完整消息变量：

```javascript
const data = Mvu.getMvuData({
  type: 'message',
  message_id: targetMessageId,
});
```

解析 MVU 命令：

```javascript
const next = await Mvu.parseMessage(commandText, baselineMvuData);
```

完整写回：

```javascript
await Mvu.replaceMvuData(next, {
  type: 'message',
  message_id: targetMessageId,
});
```

关键约束：

- `MvuData.stat_data` 是业务状态，但 `replaceMvuData` 应接收完整 `MvuData`。
- baseline 必须深拷贝。
- 最新楼 `stat_data` 为 null/空对象时，先返回内存中的最近有效完整快照；冷启动则向前回溯真实楼层，全部无效才用样例状态。
- 回退只影响读取，不把旧楼变量写入新楼；明确写回成功后再更新有效缓存。
- AI 的 JSON Patch 必须先校验，再翻译成允许的 MVU 命令。
- 不得把任意模型文本直接交给 `parseMessage()`。

## 4. 生成与第二 API

使用当前主预设：

```javascript
const result = await generate({
  generation_id: 'project-normal-1',
  user_input: prompt,
  should_stream: false,
  should_silence: true,
  max_chat_history: 0,
  custom_api: {
    apiurl: api.url,
    key: api.key,
    model: api.model,
    source: 'openai',
  },
});
```

完全不使用当前预设：

```javascript
const result = await generateRaw({
  generation_id: 'project-normal-1',
  user_input: prompt,
  should_stream: false,
  should_silence: true,
  max_chat_history: 0,
  ordered_prompts: ['user_input'],
  custom_api: {
    apiurl: api.url,
    key: api.key,
    model: api.model,
    source: 'openai',
  },
});
```

辅助接口：

```javascript
stopGenerationById(generationId);
const models = await getModelList({ apiurl: api.url, key: api.key });
```

结果可能是：

- `string`；
- `{content, tool_calls}`。

变量任务需要纯文本；只有 `tool_calls` 而没有正文时应明确失败。

## 5. 预设

| 接口 | 含义 |
|---|---|
| `getPresetNames()` | 可用预设名称 |
| `getLoadedPresetName()` | 当前 `in_use` 从哪个已保存预设加载而来 |
| `getPreset('in_use')` | 当前真正生效的现场，可能含未保存编辑 |
| `loadPreset(name)` | 真实切换酒馆主预设 |
| `replacePreset('in_use', snapshot, {render:'none'})` | 恢复未保存现场且不刷新预设 UI |

固定预设短事务：

```text
保存 loaded name + 深拷贝 in_use
→ load target
→ 等 1000ms
→ 调用 generate（只传一份 user_input）
→ 保持 target 2000ms
→ load original name
→ replace in_use snapshot
→ 释放本地锁
→ 锁外等待网络结果
```

这两个延时是当前跨 Windows/Termux 实测得出的经验值，不是 API 保证。

## 6. 深度注入与作者注释

### 迁移推荐默认

```javascript
{
  blockDepthEntries: false,
}
```

也就是设置页默认**不勾选**“屏蔽世界书按深度注入条目与作者注释”。这样不发送以下覆盖：

```javascript
{
  chat_history: {
    with_depth_entries: false,
    author_note: '',
  },
}
```

用户跨宿主实测表明，不勾选时相关内容才更能按预期注入。

### 与普通聊天历史的区别

- `context.chatHistory`：是否在 none 模式的 `ordered_prompts` 中加入 `chat_history`。
- `blockDepthEntries`：是否强制关闭深度世界书条目和作者注释。

二者独立。最终行为应通过目标设备上的真实请求内容核验。

### 当前源码事实

当前 Pastoral 功能源码已与迁移推荐一致：`blockDepthEntries` 默认 `false`，设置页默认不勾选；只有显式 `true` 才屏蔽。旧设置首次加载会迁移到版本 2 并采用新默认。

## 7. 主剧情时序

```text
捕获 beforeMessageId 与 MVU baseline
→ /send 玩家输入
→ /trigger await=true
→ 综合 MESSAGE_RECEIVED / GENERATION_ENDED / 最新楼轮询
→ 找到 id > beforeMessageId 且 role != user 的新楼
→ 对该明确 messageId 做变量后处理
```

不要只依赖一个生成事件，也不要在第二 API 返回后重新使用 latest 作为目标楼。

## 8. 伪零层

```text
getCurrentMessageId() == 0  → 唯一 UI 宿主
getCurrentMessageId() > 0   → iframe 自毁，不启动轮询
无宿主 API                  → 独立预览，使用样例数据
```

同源父页面仅做视觉隐藏：

```css
#chat > .mes:not([mesid="0"]),
#chat > .mes:not([messageid="0"]):not([mesid]) {
  display: none !important;
}
```

0 楼内部再读取 `getChatMessages('0-last')`，按真实 ID 重绘消息。聊天记录和 MVU 并没有被搬到 0 楼。

## 9. 最小安全清单

- [ ] API Key 不写日志、事件或提示词。
- [ ] AI 补丁有操作白名单和路径白名单/只读保护。
- [ ] 模型 HTML 经过 Sanitizer，而不是只删除 `<script>`。
- [ ] 固定预设始终在 `finally` 中尽最大努力恢复。
- [ ] 预设本地锁不等待网络响应。
- [ ] 写回使用明确 message ID。
- [ ] 0 楼不可编辑、不可删除。
- [ ] 同源父页面不可访问时安全降级。
