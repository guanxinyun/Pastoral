# 新项目迁移执行清单

> 按顺序执行。每一阶段都可以独立测试，不要一开始就复制整个 Pastoral 页面。

## 阶段 0：冻结现有项目

- [ ] 新建独立迁移目录或新仓库。
- [ ] 只把 Pastoral 当只读参考，不直接覆盖 `js/`、`css/`、`src/`、`test/` 或 `index.html`。
- [ ] 记录目标 SillyTavern、TavernHelper 和 MVU 版本。
- [ ] 明确目标平台：Windows、Android/Termux 或两者。

## 阶段 1：定义变量

- [ ] 编写新项目 Zod Schema。
- [ ] 调用 `registerMvuSchema(Schema)`。
- [ ] 编写匹配的 `initvar.yaml`。
- [ ] 明确脚本确定性字段与 AI 语义字段。
- [ ] 标出禁止 AI 修改的内部路径。

验收：新聊天可以初始化，`Mvu.getMvuData(...).stat_data` 与 Schema 一致。

## 阶段 2：宿主适配器

- [ ] 包装消息 API。
- [ ] 包装显示正则 API。
- [ ] 等待并包装 MVU API。
- [ ] 包装 `generate/generateRaw`。
- [ ] 包装预设 API。
- [ ] 每组能力独立探测和降级。

验收：独立预览不报错；酒馆内能列出楼层、预设和 MVU 状态。

## 阶段 3：正文处理

- [ ] 从原文提取选项。
- [ ] 从原文提取变量标签。
- [ ] 完整删除选项 payload，避免混入正文。
- [ ] 调用 `formatAsTavernRegexedString`。
- [ ] 用 HTML Sanitizer 清除危险标签、属性与 URL。
- [ ] 从深到浅解包结构容器。
- [ ] 保留有语义的内联美化。

验收：至少测试无标签正文、带外壳 HTML、带内联颜色、带思维链截断、带五类选项标签五种样本。

## 阶段 4：MVU 读写

- [ ] 读取完整 `MvuData`。
- [ ] 立即深拷贝 baseline。
- [ ] UI 只读 `stat_data`。
- [ ] 实现 UpdateVariable 标签验证。
- [ ] 实现 JSON Pointer 验证。
- [ ] 禁止 `_` 开头的内部路径。
- [ ] 实现 Patch → MVU 命令转换。
- [ ] 用 `Mvu.parseMessage(commands, baseline)` 计算新数据。
- [ ] 消息标签与完整 MvuData 写回同一楼。

验收：合法操作逐类通过，非法 JSON、未知 op、非法路径、只读路径逐类拒绝。

## 阶段 5：第二 API

- [ ] 保存 URL、Key、模型、超时和重试次数。
- [ ] Key 使用密码输入框。
- [ ] 用 `custom_api`，不在 iframe 内自行拼 `/chat/completions`。
- [ ] 给每次请求唯一 `generation_id`。
- [ ] 超时时尝试 `stopGenerationById`。
- [ ] 每次网络尝试最多一次格式纠正。
- [ ] 日常/归寝使用独立提示与快照。
- [ ] 日志中只显示目标 host，不显示 Key。

验收：连接测试、超时、401/404/429、空文本、tool_calls、格式纠正和网络重试均有明确结果。

## 阶段 6：预设策略

### none

- [ ] 使用 `generateRaw`。
- [ ] `ordered_prompts` 最后是 `user_input`。
- [ ] 默认上下文最小化。

### current

- [ ] 使用 `generate`。
- [ ] 只通过 `user_input` 发送任务。
- [ ] 不同时使用 `injects`。

### fixed

- [ ] 保存 `getLoadedPresetName()`。
- [ ] 深拷贝 `getPreset('in_use')`。
- [ ] 串行本地切换窗口。
- [ ] 切换后默认等待 1000ms。
- [ ] generate 后默认保持 2000ms。
- [ ] 恢复名称和 `in_use` 现场。
- [ ] 网络 Promise 在锁外等待。
- [ ] 目标预设不存在时降级 none。

### 深度注入推荐

- [ ] `blockDepthEntries` 默认 `false`。
- [ ] 设置页默认不勾选“屏蔽世界书按深度注入条目与作者注释”。
- [ ] 不勾选时不要发 `with_depth_entries:false` 和 `author_note:''`。
- [ ] 在目标平台检查真实请求，确认深度条目和作者注释是否正确注入。
- [ ] 只有确认污染变量任务后才允许玩家主动勾选屏蔽。

验收：Windows 与 Termux 分别确认任务只出现一次、预设正确、深度注入符合选择、原预设与未保存现场恢复。

## 阶段 7：主剧情编排

- [ ] 发主请求前捕获 baseline 与 beforeMessageId。
- [ ] `/send` 写入玩家行动。
- [ ] `/trigger await=true` 触发生成。
- [ ] 组合消息事件、生成事件和楼层轮询。
- [ ] 只接受新的非 user 楼层。
- [ ] 普通多 API 在主楼确认后运行。
- [ ] 归寝按“日常 → 确定性 → 归寝 → 最终锁定”执行。
- [ ] 所有成功和失败路径都结束 loading 状态。

## 阶段 8：状态连续性与交互适配

- [ ] 最新楼 `stat_data` 为空时读取最近一楼有效完整 MvuData。
- [ ] 缓存返回深拷贝，不把旧快照写回新楼。
- [ ] 手机沉浸模式默认经营页，并可切换经营页/剧情页。
- [ ] 桌面沉浸仍保持双页等分。
- [ ] 所有设备员工卡支持摘要点击展开，展开状态跨 MVU 重绘保持。
- [ ] 员工日薪使用统一铜币格式。

## 阶段 9：伪零层（可选）

- [ ] 宿主判定模块最先执行。
- [ ] 仅 0 楼存活。
- [ ] 非 0 楼不启动计时器或事件监听。
- [ ] 同源时隐藏父页面非 0 楼。
- [ ] 0 楼内聚合 `0-last` 真实消息。
- [ ] 所有气泡保留真实 message ID。
- [ ] 0 楼禁止编辑删除。
- [ ] 跨源时安全降级。
- [ ] Hash 含末楼 ID 和内容哈希，避免同长度编辑漏刷新。

## 阶段 10：发布前验证

- [ ] 单元测试覆盖正文、Patch、MVU、API、预设事务。
- [ ] jsdom/浏览器测试覆盖 0 楼、非 0 楼和独立预览。
- [ ] 真实 Windows 宿主测试。
- [ ] 真实 Android/Termux 宿主测试。
- [ ] 检查日志无 Key、完整提示词和完整变量快照。
- [ ] 检查构建产物与源文件一致。
- [ ] 检查新项目没有依赖 Pastoral 专属字段名。
